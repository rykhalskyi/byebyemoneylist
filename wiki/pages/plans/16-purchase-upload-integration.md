# 16. Nextcloud Purchase Upload (Integration 2.0) — Implementation Plan

Companion server plan: `~/Source/byebyemoneylist-ns/wiki/pages/plans/purchase-import.md`.

Replaces the removed bidirectional OCS mirror (plans 06–09, removed in plan 15) with a
much smaller, deliberately one-way flow: **phone → server only, for purchase
tracking**. The phone never pulls, never maps, and never stores server ids.

## Goal

When Nextcloud credentials are configured, a user can send a **finished purchase
list** to Nextcloud. The phone serializes the list to a shared JSON contract and
POSTs it. The Nextcloud app stores it as an *incoming* list; the user then maps
categories, store and products on the web (optionally AI-assisted) and approves it
into a normal list that keeps the client's list id.

## Decisions

- **D1 — Manual only.** Upload is a menu action on a finished purchase list. No
  automatic upload after `processPurchase`, no background sync, no retry worker.
- **D2 — Finished purchase lists only.** Eligible: `kind == PURCHASE` (and
  defensively `isFinished && !isIncome && !isSubscription`). To Buy, income and
  subscription lists are excluded.
- **D3 — One-way.** No pull, no update propagation, no deletes. The folder-based
  sharing (`ListSyncEngine`, `SyncFolderRepository`) is untouched.
- **D4 — Phone contains no mapping logic.** It sends raw display names plus optional
  hints (barcode, category name, store name). All category/store/product matching
  happens on the server.
- **D5 — Stable per-list upload UUID.** A new nullable `uploadId` on
  `shopping_lists` is generated lazily at first upload and reused on resend. The
  server uses it as the incoming dedupe key and as the final `bbml_lists.id`.
- **D6 — Reuse the old connection code.** URL normalisation, Basic Auth, the
  `OCS-APIRequest` header and the `/ocs/v2.php/apps/byebyemoneylist` path probing
  are recovered from `git show 2b329bf^:.../data/sync/NextcloudApiClient.kt`. The
  password stays in `EncryptedSharedPreferences`.
- **D7 — Additive Room migration only.** `shopping_lists` gains `uploadId` and
  `lastUploadedAt`; version `32 → 33`. No existing column or table is removed.
- **D8 — Idempotent resend.** While the server import is not approved, sending the
  same `listId` again replaces its content and recomputes suggestions. After
  approval the server answers "already imported" and the phone treats it as success.
- **D9 — No build flag.** The feature is always compiled in and hidden at runtime
  by a "not configured" check (URL/username/password blank).

## Shared JSON contract (`bbml.purchase-upload/1`)

The exact same contract is implemented in the Kotlin client and the PHP server.
Field names are camelCase; dates are RFC 3339 in UTC; amounts are major currency
units (e.g. `1.29`, not cents).

```json
{
  "schema": "bbml.purchase-upload/1",
  "clientId": "5c1e1f7a-7d9c-4f0e-9a1b-3f0a7d1e2b44",
  "listId": "b1f0c7d2-3b1e-4a67-9c55-0e1d2f3a4b5c",
  "list": {
    "name": "Purchase 09.11.2026",
    "createdAt": "2026-11-09T18:30:00Z",
    "purchaseDate": "2026-11-09T19:05:00Z",
    "currency": "€",
    "finalTotal": 42.37,
    "store": {
      "name": "Lidl",
      "address": "Hauptstr. 1",
      "receiptName": "LIDL"
    },
    "categories": [
      { "name": "Groceries", "isIncome": false }
    ]
  },
  "items": [
    {
      "lineId": "1728571200000",
      "name": "Milk 1l",
      "quantity": 1.0,
      "unitPrice": 1.29,
      "discount": null,
      "isCoupon": false,
      "barcode": "4001234567890",
      "categoryHint": "Dairy"
    },
    {
      "lineId": "1728571200001",
      "name": "Store coupon",
      "quantity": 1.0,
      "unitPrice": 0.0,
      "discount": 0.50,
      "isCoupon": true,
      "barcode": null,
      "categoryHint": null
    }
  ]
}
```

Rules:

- `schema` is required and must equal exactly `bbml.purchase-upload/1`.
- `listId` is a UUID v4 generated by the phone. It is **stable across resends** and
  becomes the server list id after approval.
- `clientId` is the existing stable install UUID
  (`PreferencesManager.getSyncUserId()`); diagnostic only.
- `name` is the item display name: `customName` when present, otherwise the catalog
  product name. The phone never sends local product/category/store ids.
- `quantity` > 0. `unitPrice` and `discount` are nullable and non-negative.
- `isCoupon` is true when the local item has `productId == 0` on a purchase list.
  Coupons are sent for transparency but default to *skip* on the server; the list
  `finalTotal` still carries the money.
- `barcode` and `categoryHint` are optional mapping hints, never authoritative.
- Unknown fields are ignored by both sides for forward compatibility.
- Server limits: max 1000 items, max 1 MB body, `name` ≤ 255 chars.

## Client architecture

New package `app/src/main/java/com/otakeeesen/byebyemoneylist/data/integration/`:

| File | Responsibility |
|---|---|
| `PurchaseUploadDto.kt` | `@Serializable` request/response models for the contract and OCS response wrappers. |
| `PurchaseUploadApiClient.kt` | OkHttp + Basic Auth; recovered URL/path logic; `testConnection()` and `upload(payload)`. |
| `PurchaseUploadRepository.kt` | Eligibility guard, payload assembly from Room, `uploadId` persistence, result mapping. |
| `PurchaseUploadResult.kt` | `Success(sentAt, alreadyImported)`, `NotConfigured`, `NotEligible`, `AuthError`, `AppNotFound`, `Rejected(message)`, `NetworkError`. |

Wire in `ByeByeMoneyApplication`:

```kotlin
val purchaseUploadRepository by lazy {
    PurchaseUploadRepository(this, database, preferencesManager, PurchaseUploadApiClient())
}
```

### Payload assembly

- Load `ShoppingListEntity`; verify eligibility.
- Ensure `uploadId` (generate `UUID.randomUUID().toString()` if null and persist).
- Store: `storeDao().getStoreById(list.storeId)` → `name`, `address`, `receiptName`.
- List categories: `getCategoriesForShoppingListSync(list.id)` → `CategoryEntity`
  names + `isIncome`.
- Items: a **new DAO projection** `getUploadItemsForList(listId)` joining
  `shopping_list_items` → `products` → `categories`, returning:
  `itemId, productId, quantity, itemPrice, latestPrice, discount, customName,
  productName, barcode, categoryName, position`.
  - `name = customName ?: productName ?: "item_<id>"`
  - `unitPrice = itemPrice ?: latestPrice ?: 0.0`
  - `lineId = itemId.toString()`
  - `isCoupon = productId == 0L`
- Dates: `Instant.ofEpochMilli(...).toString()` (already UTC RFC 3339).
- `currency = preferencesManager.getCurrencySymbol()?.takeIf { it.isNotBlank() }`.
- `clientId = preferencesManager.getSyncUserId()`.

### HTTP client

Recover from `2b329bf^` and trim to:

```kotlin
suspend fun testConnection(): Result<Boolean> =
    request("GET", "/api/categories?format=json") { true }

suspend fun upload(payload: PurchaseUploadRequest): Result<PurchaseUploadResponse> =
    request("POST", "/api/purchase-imports", jsonBody(payload)) { body ->
        parseOcsOrDirect<PurchaseImportResponse>(body).import
    }
```

Headers: `Authorization: Basic ...`, `OCS-APIRequest: true`,
`Accept: application/json`, `Content-Type: application/json`.
Path candidate `"/ocs/v2.php/apps/byebyemoneylist"`, cached after first success.
`404` → `AppNotFound`; `401/403` → `AuthError`; `409` from the server (already
approved) is treated as `Success(alreadyImported = true)`.

### Settings UI

- New `ui/components/settings/NextcloudUploadSettingsScreen.kt` + route
  `Screen.NextcloudUploadSettings` + `MainScreen` wiring + a Settings row
  ("Nextcloud") showing "Configured"/"Not configured".
- Fields: server URL, username, app password (`PasswordVisualTransformation`),
  Test connection button. Save on change:
  - URL/username in `prefs` (`nextcloud_url`, `nextcloud_username` — same keys as
    the removed feature, so existing installs keep them).
  - Password in `encryptedPrefs` (`nextcloud_password`).
- "Test connection" calls `PurchaseUploadApiClient.testConnection()` with the
  current values and shows success/failure toasts.
- No polling, no sync status, no list editor.

### List action UI

- `ShoppingListCard`: new optional callbacks `onSendToNextcloud`, `isUploading`,
  `isUploadSent`. Add a menu item (only for eligible lists) labelled
  `nextcloud_send` / `nextcloud_send_again`, disabled while uploading.
- `ShoppingListsScreen`: pass the callbacks and show a Toast from a ViewModel
  `uploadMessage`.
- `ShoppingListViewModel`: constructor gains `purchaseUploadRepository`;
  `sendToNextcloud(list)` launches on `ioDispatcher`, exposes
  `uploadingListIds: Set<Long>` and a one-shot `uploadMessage`, then clears it.
- `ShoppingList` domain gains `uploadId: String? = null` and
  `lastUploadedAt: Long? = null` (mapped in `toDomain`/`toEntity`) so the card can
  render "Send again".

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Server contract drifts from the phone | Uploads rejected/misparsed | Contract is specified once here and in the server plan; schema string is validated both sides; controller tests assert it. |
| User loses Nextcloud password on upgrade | Feature appears unconfigured | Reuse the old preference keys; password remains encrypted. |
| Duplicate uploads create duplicate lists | Bad data | `uploadId` + `(owner, clientListId)` unique index; approved imports are immutable and return duplicate. |
| Room migration breaks existing lists | Data loss | Additive `ALTER TABLE` only + `migrate32To33` test + Room schema validation. |
| Basic Auth rejected by Nextcloud | No uploads | Use an app password (not the account password); Test connection gives an explicit message. |
| Coupons inflate item totals | Wrong analytics | Coupons default to *skip* server-side; `finalTotal` is authoritative. |
| Large receipts / slow network | Timeout/ANR | Network on `Dispatchers.IO`, 15 s timeouts, 1000-item / 1 MB server cap, one-shot user action. |

## Testing checklist

- [ ] Eligible list shows the send action; To Buy/income/subscription do not.
- [ ] Unconfigured server hides the action / settings says "Not configured".
- [ ] First upload generates `uploadId`; resend reuses it.
- [ ] Payload includes store, categories, item names, quantities, prices, discount,
      coupon flag, barcode, category hint, RFC 3339 dates.
- [ ] Success stores `lastUploadedAt` and shows "Send again".
- [ ] 401 shows a credentials message; 404 shows app-not-installed; network error is
      non-destructive (list unchanged).
- [ ] Server already-approved duplicate is treated as success.
- [ ] `migrate32To33` passes; existing lists keep all data.
- [ ] Folder sharing still works.

## Out of scope

- Pulling anything from Nextcloud to the phone.
- Automatic upload after purchase.
- Retry/background workers, upload history screen, cancel/delete on the server.
- Mapping categories/stores/products on the phone.
- Sending To Buy, subscription or income lists.
- Any server-side deletion/unapproval triggered from the phone.
- Removing the legacy folder-sharing feature.

## Open questions

1. **Resend after approval.** Current decision: server returns "already imported".
   If users need to correct an approved import, a later "re-import as revision"
   flow can be added (new incoming row, same final list id is not possible).
2. **Currency symbol only.** The contract sends the display symbol (`€`), not an ISO
   code, because the app stores only a symbol today. If server analytics needs an
   ISO code, add a `currencyCode` field later.
3. **Coupons.** Default skip. If coupon-as-item is needed for item-level analytics,
   the server can map them to a dedicated "Coupon" product.
